## Haunting and Blasting modules, Smelting fixes

Two new tiered Enhanced Shulker Box modules, plus two fixes to the Smelting module. Mixing and
Mechanical Crafting modules are dropped from the roadmap.

### Behaviour

- **Haunting Upgrade Mk I/II/III** uses Create haunting recipes (`create:haunting`), including CESG's
  `cesg:end_stone_from_haunting` (sandstone → end stone). It also applies every other haunting recipe,
  e.g. stone → infested stone and potato → poisonous potato; the tooltip warns about this.
- **Blasting Upgrade Mk I/II/III** uses vanilla `minecraft:blasting` recipes only (not smelting), so in
  practice it handles metals. The result is `getResultItem`, a single output. Items with a max stack
  size of 1 (tools, armour) are skipped so they are not melted into nuggets.
- Both work like Crushing and Washing: placed boxes only, every 20 ticks, paused while the screen is
  open, 1/2/4 conversions per second for Mk I/II/III, only the highest installed tier counts. Each
  conversion is simulated first and commits only if all outputs fit, so a full box holds its input.
- Run order in a pass: Crushing, Washing, Haunting, Blasting.

### Priority rule

- Crushing and Washing share items as before (unchanged).
- Haunting skips any item that an **installed** Crushing or Washing module can process.
- Blasting skips any item that an installed Crushing, Washing or Haunting module can process.
- "Can process" lookups are cached per item and per recipe manager, so a datapack reload clears them.

Consequences worth knowing: with Crushing installed, sandstone is milled to sand rather than haunted
to end stone; with Washing installed, sand is washed rather than haunted to soul sand. Haunting +
Washing farms pearl dust in one box (sandstone → end stone → pearl dust), the same as a fan setup.

### Smelting fixes

- Smelting skips items with a max stack size of 1, so tools and armour are no longer stored as nuggets.
- With a Crushing module installed, Smelting stops at raw ores and ore blocks (`c:raw_materials`,
  `c:ores`) that a Crushing module can process, so Crushing gets them and keeps its bonus. Other
  crushable items (cobblestone, or sand where an addon adds sand crushing) keep smelting as before;
  an earlier version held back everything crushable, which made a 59-addon pack stop making glass.
  The check reads the box's own upgrade slots, so it also applies to unplaced boxes, where Crushing
  does not run; those items stay raw until the box is placed.

### Textures

`haunting_upgrade_t1..t3.png` and `blasting_upgrade_t1..t3.png` are generated by
`tools/textures/generate_processing_module_icons.py`. It copies each tier's frame from
`washing_upgrade_t<tier>.png` (Mk I iron, Mk II brass, Mk III teal) and draws a soul campfire or a
blast-furnace motif inside it. `processing-modules-icons.png` shows old and new icons at 16×.

### Validation (2026-11-13)

- `./gradlew runData`: only the expected new and changed generated files were kept; line-ending-only
  rewrites and an unrelated `gateway_frame.json` reordering were reverted.
- `./gradlew clean build runGameTestServer --console=plain`: build successful, "All 41 required tests
  passed" (33 existing + 8 new in `ProcessingModuleTest`). `cesgRecipesHaveNoSameInputTwin` checked
  58 CESG recipes against 2,906 loaded with no conflicts. `run/gametest/mods` was empty.
- `python tools/ponder/verify.py`: all checks passed.

New GameTests: Haunting lookup resolves sandstone to `cesg:end_stone_from_haunting`; Haunting turns
sandstone into end stone; Blasting turns raw iron into ingots and leaves sand, cobblestone, beef and an
iron sword alone; Crushing + Blasting crushes iron ore instead of blasting it; Haunting + Washing
washes sand instead of haunting it; a full box keeps its input and drops nothing; a placed box with
Haunting Mk I converts sandstone within 40 ticks; Smelting leaves an iron sword alone and leaves raw
iron for an installed Crushing module.

### Not verified

- Textures, names and tooltips in a running client, and JEI/EMI display of the new recipes.
- The Create addon pack audit (`run/gametest/mods`) was not re-run with the new recipes.
